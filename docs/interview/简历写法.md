# FitAgent 简历写法

> 只保留你能在面试中结合源码讲清楚的内容；不要把“计划自动下发设备”“官方 Coros OAuth 已生产化”“医学诊断”“多 Agent”写成已完成。

## 短版（3–4 行）

**FitAgent — 可解释 RAG 私人健身 Agent**

- 基于 FastAPI、LangGraph、Qdrant 与 Vue 3 构建受约束的混合型 Agentic RAG 健身应用；通用问题走 Dense + BM25 + RRF 的 Direct RAG，个性化问题才按需编排画像、运动数据和已确认记忆工具，并通过 SSE 返回证据卡片。
- 设计用户可控三层记忆：会话摘要只取用户消息，长期事实经候选—确认—撤销/过期生命周期管理，规避 LLM 输出污染与隐私风险。
- 实现基于 Coros 近 4 周数据、RAG 证据及确定性安全策略的结构化周训练计划；服务端校验强度、训练天数和证据 ID，反馈按天幂等更新。
- 重构 Coros stdio MCP 客户端，解决 Windows pipe 超时、并发 JSON-RPC 串扰和同日多活动覆盖问题，补充 Alembic 迁移与 pytest 回归测试。

## 长版（完整项目经历）

**项目名称：FitAgent — 可解释 RAG 与用户可控记忆的私人健身 Agent**  
**项目角色：LLM 应用开发 / 全栈开发**  
**技术栈：Python、FastAPI、LangChain/LangGraph、DashScope、Qdrant、BM25、MySQL、SQLAlchemy/Alembic、Vue 3、ECharts、MCP**

术语说明：DashScope 指阿里云百炼模型服务，项目通过 LangChain 的 `ChatTongyi` 与 `DashScopeEmbeddings` 接入聊天、视觉与向量模型；ECharts 用于训练负荷、HRV 与睡眠等设备数据的前端可视化。

**项目描述**

面向运动健康场景构建 AI 教练应用，支持知识问答、用户画像、健康报告提取、Coros 数据同步、用户可控跨会话记忆和受安全策略约束的周训练计划。重点解决 RAG 证据可追溯、个性化授权边界与生成计划安全校验。

**核心工作**

1. 设计混合 Agentic RAG 路由：将通用知识请求分流到 Direct RAG，使用 Qdrant Dense 与 BM25 双路召回、RRF 融合、revision/alias 发布；指代/复合问题最多扩展为两个子查询，个性化请求进入 LangGraph ReAct，并对工具步数、预算与轨迹审计做约束。
2. 设计三层记忆模型：用最近消息、可重建短期摘要和 `memory_facts` 长期记忆分别承载不同语义；引入 `proposed/confirmed/revoked` 状态、过期和替换关系，确保模型不能自动写入用户长期事实。
3. 实现自适应训练计划服务：聚合 Coros 近四周训练负荷、睡眠、HRV、活动类型等数据；将伤病、恢复指标、RPE/疼痛转化为确定性强度上限，再以 Pydantic JSON schema 和业务规则校验模型输出与 RAG 证据。
4. 重构 Coros MCP adapter：对 stdio JSON-RPC 完整请求/响应加锁，使用 reader thread 实现 Windows 超时，失败后销毁并重建进程；将活动唯一键改为外部 ID，修复同日多活动覆盖；Agent 侧仅暴露受限区间聚合和经候选确认的单次活动白名单指标，并编写兼容 MySQL 外键索引的 Alembic 迁移。
5. 完善工程质量：分离 API/Service/External Adapter 边界，为记忆、计划和 MCP 新增单元/接口测试；维护 README、架构、API 契约、执行计划和面试演示脚本。

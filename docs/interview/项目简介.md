# FitAgent：可解释、可控个性化的私人健身 Agent

FitAgent 是一个面向健身与运动健康场景的 LLM 应用。用户可以填写健身画像、同步 Coros 运动数据、上传健康报告，并通过流式聊天获得训练、动作、营养与恢复建议。

项目的重点不是“做一个能聊天的健身机器人”，而是解决三个落地问题：**知识建议是否可追溯、个性化信息是否由用户控制、训练计划是否有可验证的安全边界**。

```text
通用知识问题 → Dense + BM25 + RRF 的 Direct RAG → 带证据编号与来源卡片的回答
个性化问题 → LangGraph ReAct Agent → 按需读取画像 / 已确认记忆 / 运动摘要 / RAG
显式生成计划 → Coros 聚合快照 + 反馈 + 安全策略 + RAG → 结构化周计划
```

## 用户闭环

1. 用户填写目标、每周可训练天数、经验、伤病与偏好；可上传健康报告，但识别结果必须确认后才写画像。
2. 用户在数据面板主动同步 Coros，原始活动按外部记录 ID 幂等保存，避免同一天多次训练被覆盖。
3. 聊天中提及城市、目标、伤病、饮食等信息时，系统只创建“待确认”记忆候选；用户在“我的记忆”确认后才会供 Agent 使用，并可撤销或等待过期。
4. 用户在“本周计划”显式生成计划。后端先执行伤病、睡眠、训练负荷、疲劳、RPE/疼痛规则，再让模型在强度上限和 RAG 证据范围内输出 JSON；失败会被 schema 和服务层拒绝。
5. 用户提交每天的完成情况、RPE 与疼痛反馈，下一版计划读取这些反馈做恢复判断。

## 技术架构

| 层 | 主要技术 | 职责 |
|---|---|---|
| 前端 | Vue 3、Pinia、Naive UI、ECharts | 流式对话、证据卡片、Coros 数据面板、记忆和计划操作 |
| API | FastAPI、Pydantic | JWT 鉴权、REST/SSE 契约、输入输出校验 |
| Agent / RAG | LangChain、LangGraph、DashScope、Qdrant、BM25 | Direct RAG 快速路径、受预算约束的工具调用、可追溯检索 |
| 业务服务 | MemoryService、TrainingPlanService、FitnessSnapshot | 记忆生命周期、计划安全策略、设备数据受限聚合 |
| 数据与迁移 | MySQL、SQLAlchemy、Alembic | 用户/画像/会话/记忆/计划/反馈/运动数据持久化 |
| 设备适配 | 社区 Coros MCP + 本地 stdio JSON-RPC | 固定提交、隔离工具环境、只读数据拉取、串行与超时重建 |

## 演示时的边界说明

- RAG 证据是回答的参考来源，不是医学诊断。
- 训练计划的安全规则是产品级门禁，不替代医生或专业教练。
- 当前不自动把模型计划下发到 Coros，避免模型输出直接造成外部不可逆操作。
- 本地 Coros MCP 固定到社区版提交，并在隔离 `.tools` 环境以只读权限运行；已完成真实账号认证、端到端同步和 MySQL external key 去重验证，但不把它表述为官方 Coros OAuth 集成或自动下发训练计划。

# mem0 单存储长期记忆

用户已批准：mem0 负责 LLM 提取与语义检索；由模型自己决定是否调用 `get_confirmed_memories(query)`；确认、撤销、有效期都存入记忆元数据。MySQL 仅保留账号、完整聊天、会话摘要和训练等业务。旧 `memory_facts` 保留待显式迁移，运行时不再读写它。

## 存储职责

- 主向量库保存记忆正文、向量和元数据，是长期记忆唯一事实源。
- Entity Store 保存实体向量，使用 `linked_memory_ids` 关联主库；是否生成实体依赖安装的实体提取能力。
- mem0 SQLite 保存变更日志，并按 `session_scope` 保留最近 10 条消息供提取使用。它不替代 FitAgent 完整聊天记录。

以上已核对安装版本 mem0ai 2.0.20。首版使用基础包和语义检索，不安装 NLP extras，不对 Entity/BM25 增益作承诺。

## 数据流

用户消息保存到 MySQL 后，线程池调用 mem0 `add(infer=True)`。候选携带 `status=proposed`、`source_message_id`、`source=chat` 和 `expires_at`，按用户与会话限定提取上下文，按用户与来源消息 ID 判断重复处理。只提交用户消息。重复处理同一消息返回已有候选，包括撤销项，不重新生成已忽略的内容。

确认、编辑、撤销直接调用适配器修改记忆元数据；用户主动创建使用 `infer=False` 保留原文。更新前验证记录所属用户。无法完成外部写入时接口返回错误，不声称更新成功。

查询只在模型调用工具时发生，工具没有个人关键词硬门槛。适配器按用户、confirmed 状态语义检索；服务再次校验用户与状态、到期时间和最新内容，按相关性顺序去重并限制条数/字符数。空召回与外部故障使用不同返回信息。

自定义元数据状态不能依靠模型传入。SDK 与向量库连接仅由适配器拥有，核心服务返回应用领域类型。LLM 与向量库超时、模型、维度、collection、路径均可配置。

## 迁移和失败边界

提供 `python -m app.services.memory_migration`，默认仅预览；显式 `--apply` 时复制旧记忆到 mem0，保留原状态、来源、有效期及 `legacy_id`。重跑按用户和 legacy_id 去重。源表和源数据不删除、不再参与在线查询。

候选提取失败不阻断聊天，但记录脱敏错误。管理接口失败返回 503。撤销成功后下次查询排除该记录；并发查询已取出的上下文无法追溯撤回。mem0 SDK 的向量更新和 SQLite 日志不是一个跨存储事务，不在应用层再建同步数据库。

## 验证

应用服务/API 使用可控外部后端测试；实际 SDK 使用本地 Qdrant 和确定性模型验证提取及召回。测试覆盖候选不可读、确认、撤销、过期、跨用户隔离、最新状态复核、空召回、错误区分、重试幂等、迁移预览及源数据保留。原会话摘要、路由与 SSE 契约保持。
